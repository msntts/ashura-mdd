# UIコンポーネントライブラリ(デザインシステム)ドメインモデル(仮想DSL)

```
# ============================================
# コンテキストマップ
# ============================================
コンテキストマップ {
  文脈 基盤     "デザイントークン。色・余白・字・動きの語彙"
  文脈 部品     "コンポーネント単体。状態と振る舞い"
  文脈 合成     "部品の組み合わせ規則とパターン"

  # --- 外部上流 ---
  文脈 デザイン原典 (外部: Figma) "デザイナーの決定の源"
  関係 デザイン原典 -> 基盤 (上流/下流, 腐敗防止層: トークン取込変換)
    # Figmaの生値を直接使わない。必ずトークンに変換して取り込む
  関係 基盤 -> 部品   (準拠: 部品はトークン以外の値を使えない)
  関係 部品 -> 合成   (公開インターフェース: propsと公開状態のみ)

  # --- 横断制約(このドメインの「不変条件」は見た目の整合そのもの) ---
  横断制約 {
    トークン強制:   全部品において生値(#hex, px直書き)の使用を禁止する   # 静的検査可能
    語彙統一:       同一概念に同一名。variant名は 主/副/危険 の3語のみ。
                    「main」「primary」「default」の混在を禁止   # ←見た目の整合の言語面
    到達可能性:     全ての操作可能部品はキーボードのみで操作完遂できる
    コントラスト:   前景/背景のコントラスト比 >= 4.5:1(AA準拠)   # トークンの組で静的検査
    動きの節度:     全アニメーションは 動き.標準(200ms) か 動き.強調(300ms) のみ。
                    利用者が「動きを減らす」設定なら全て無効化
  }
}

# ============================================
# 文脈: 基盤(用語集がトークン表になる)
# ============================================
文脈 基盤 {
  用語集 トークン {
    色.主       : 値  参照(デザイン原典)   "ブランドの中核色"
    色.危険     : 値  参照(デザイン原典)   "破壊的操作にのみ使う"   # 意味論つき
    余白.1..8   : 値  4pxの倍数スケール    "中間値は存在しない"
    字.見出し/本文/注釈 : 値
    動き.標準/強調      : 値
  }
  不変条件 {
    色.危険 は 削除・取消不能操作 以外の部品に出現しない   # 色の意味の保護
    余白スケール外の値は定義できない
  }
}

# ============================================
# 文脈: 部品(集約=コンポーネント。状態機械が主役)
# ============================================
文脈 部品 {

  集約 ボタン {
    props: { variant: 主|副|危険, 大きさ: 大|中|小, 無効?: 真偽 }

    状態: 通常 -> ホバー -> 押下 -> 通常
    状態: 通常 -> フォーカス(キーボード)      # マウスと独立の系
    状態: * -> 無効                            [条件: props.無効]
    状態: 通常 -> 処理中                       [契機: 非同期アクション開始]
    禁止 無効 -> 押下          # 無効中はクリックが発火しない(見た目だけ無効はバグ)
    禁止 処理中 -> 押下        # 二度押し防止は部品の責務 ←ビジネス判断

    不変条件 {
      フォーカス状態では フォーカスリング が必ず視認できる(コントラスト >= 3:1)
      処理中 では 操作不能 かつ 進行表示 が出る
      大きさによらず タップ領域 >= 44x44px   # 見た目より当たり判定が大きくてよい
    }
  }

  集約 モーダル {
    状態: 閉 -> 開 -> 閉
    遷移 開 -> 閉 [契機: 閉じるボタン | Escキー | 背景クリック(props.軽量==真 のとき)]
    不変条件 {
      開 のとき フォーカスはモーダル内に閉じ込められる(Tabが外に漏れない)
      閉 に戻ったとき フォーカスは開く前の要素に復帰する   # a11yの古典的バグの明文化
      開 は同時に高々1枚(多重モーダル禁止) ←ビジネス判断
    }
  }

  # --- 決定表: variant × 状態 → トークン(見た目の整合の本体) ---
  決定表 ボタン外観 {
    入力: (variant, 状態)   出力: (背景, 文字色, 枠)

    | variant | 状態     | 背景          | 文字色      |
    |---------|----------|---------------|-------------|
    | 主      | 通常     | 色.主         | 色.白       |
    | 主      | ホバー   | 色.主.濃(+1段) | 色.白       |
    | 危険    | 通常     | 色.危険       | 色.白       |
    | *       | 無効     | 色.灰.薄      | 色.灰       |
    | *       | 処理中   | (通常と同じ)  | (通常と同じ)|

    検査: 全セルの(背景, 文字色)組がコントラスト制約を満たす   # 表×制約の直積を静的検査
    検査: 全variant × 全状態 のセルが定義済み(見た目の未定義状態を許さない)
  }
}

# ============================================
# 文脈: 合成(何を何に入れてよいか)
# ============================================
文脈 合成 {
  合成規則 {
    モーダル 内に モーダル を置けない        # 不変条件の構文的裏付け
    ボタン 内に 操作可能部品 を置けない      # 入れ子の操作対象は曖昧なa11y違反
    フォーム部品 は ラベル と必ず対で使う    # 単体使用を型レベルで禁止
  }
  性質 {
    独立性: 任意の部品は 他の部品のCSSに依存せず 単体で正しく描画される
      # 検証: 部品を1個だけ置いたページで視覚スナップショットが仕様と一致
  }
}

# ============================================
# 検証(このドメイン固有: 視覚回帰と人間の目)
# ============================================
検証 {
  機械で閉じる層 {
    トークン強制・語彙統一・合成規則     -> 静的検査(LSP/リンタ)
    コントラスト・決定表の網羅           -> 表の直積検査
    状態遷移・フォーカス管理             -> 状態機械テスト+axe系a11y監査
    二度押し防止・Escで閉じる            -> 操作シーケンステスト
  }
  人間ゲートが残る層 {
    視覚スナップショット差分の承認:
      意図した変更か否かの判定は人間のみ   # 「美しいか」は機械検証の外
    ただし 差分の発生検知と局所化は機械が行い、
    人間は差分画像の承認/差戻しだけを行う   # レビュー対象は縮む
  }
}

# ============================================
# 横断的性質(検証者エージェントへの攻撃指示)
# ============================================
性質 {
  トークン閉包性: 生成された全CSSの色・余白・時間の値はトークン定義の像に含まれる
  キーボード完遂性: マウスイベントを全て無効化しても、全部品の全操作が完遂できる
  テーマ交換耐性: トークンの値だけを差し替えたとき(ダークモード)、
                  状態機械・a11y性質は一切変化しない   # 見た目と振る舞いの直交性
  スナップショット安定性: モデル・トークン不変のまま再生成しても視覚差分ゼロ
                  # LLM非決定性が「見た目」に漏れないことの検証
}
```
