# オンライン対戦すごろく ドメインモデル(仮想DSL)

```
# ============================================
# コンテキストマップ(今回初めて複数コンテキストが登場)
# ============================================
コンテキストマップ {
  文脈 マッチング   "対戦相手を見つけ、卓を立てる"
  文脈 対戦進行     "接続・手番・時間を管理する。ゲームルールの宿主"
  文脈 ゲームルール "すごろくそのもの。sugoroku-model.md をそのまま取り込む"   # ★再利用
  文脈 対戦記録     "戦績の保存と閲覧"

  関係 マッチング -> 対戦進行   (上流/下流: 卓確定イベントを引き渡す)
  関係 対戦進行 -> ゲームルール (準拠: ルールに一切手を加えない)   # ★重要な宣言
  関係 対戦進行 -> 対戦記録     (イベント連携, 結果整合)

  # --- 横断制約 ---
  横断制約 {
    サーバー権威: 盤面の真実はサーバーのみが持つ。クライアント申告の位置・出目は信用しない
    出目の生成:   サイコロはサーバーで振る(クライアントは要求のみ)   # チート防止=信頼境界
    個人情報:     対戦記録 に渡るのはプレイヤーIDと戦績のみ(表示名の生値は渡らない)
  }
}

# ============================================
# 文脈: マッチング
# ============================================
文脈 マッチング {

  フロー 卓成立 {
    コマンド 対戦を希望する -> イベント 待機列に追加
    ポリシー: 待機列に2人以上 のとき -> コマンド 卓を立てる -> イベント 卓成立

    タイムアウト: 待機列に追加 から 90秒 以内に 卓成立 なければ
      -> イベント マッチング失敗 -> コマンド 待機列から除去(通知: "相手が見つかりませんでした")

    # --- 補償(サーガ) ---
    補償: 卓成立 後、対戦進行 の 卓準備 が失敗したら
      -> コマンド 卓を解散 -> 両プレイヤーを待機列の先頭へ戻す   # 並び直しの不利益を与えない ←ビジネス判断
  }

  性質 {
    重複不在: 同一プレイヤーが待機列に2回以上存在しない(連打しても)   # 冪等性
    取り残し不在: 待機列のプレイヤーは必ず 卓成立/失敗/自主離脱 のいずれかに到達する
  }
}

# ============================================
# 文脈: 対戦進行
# ============================================
文脈 対戦進行 {

  # --- 集約: 接続(プレイヤーごと。ゲーム状態とは別の状態機械) ---
  集約 接続 {
    状態: 接続中 -> 切断中 -> 復帰 | 離脱確定
    遷移 接続中 -> 切断中   [契機: ハートビート途絶 5秒]
    遷移 切断中 -> 復帰     [契機: 再接続, 条件: 切断から 60秒以内]
    遷移 切断中 -> 離脱確定 [契機: 60秒経過]
    禁止 離脱確定 -> 復帰            # 離脱後の出戻りは新規マッチングから ←ビジネス判断
  }

  # --- フロー: 手番の時間管理(ゲームルールの外側から包む) ---
  フロー 手番時間 {
    ポリシー: ゲームルール.手番交代 のとき -> タイマー開始(30秒)
    タイムアウト: 30秒 以内に ゲームルール.出目確定 なければ
      -> コマンド 自動で振る(サーバーが代行)   # 放置でゲームを止めない
      # 代替案「手番スキップ」は不採用: ゲームルール側に「スキップ」効果が既存のため
      # 混同を避け、時間切れ=自動プレイ と一本化 ←ビジネス判断
  }

  # --- フロー: 切断時の扱い(接続状態機械 × ゲーム進行 の縫い目) ---
  フロー 切断処理 {
    ポリシー: 接続.切断中 かつ 本人の手番 のとき -> 手番時間は止めない
      # 切断は待ってもらえない。30秒で自動プレイに移行 ←ビジネス判断(対戦相手の体験優先)

    ポリシー: 接続.復帰 のとき
      -> コマンド 盤面を再送(ゲームルール.履歴再現性 に依拠)   # ★イベント列から状態を再構成
    ポリシー: 接続.離脱確定 のとき
      -> コマンド 残りを自動プレイに切替 -> イベント 不戦扱い記録
      # 代替案「即時没収勝ち」は不採用: 3人以上対戦で残者のゲームが壊れるため
  }

  # --- 依存と失敗セマンティクス ---
  依存 {
    ゲームルール   (必須,  失敗時: 卓を強制終了し全員に復旧不能を通知)  # ここが死んだら対戦は成立しない
    対戦記録       (任意,  失敗時: ローカル保持して後送)                 # 記録落ちで対戦は止めない
    通知サービス   (任意,  失敗時: 無通知で続行)
    マッチング     (起動時のみ必須, 対戦中は不要)   # 依存の時間性
  }
}

# ============================================
# 文脈: ゲームルール
# ============================================
文脈 ゲームルール {
  取込 "sugoroku-model.md" {
    変更禁止                       # 対戦化にあたりルール本体は1行も変えない
    公開イベント: 手番交代, 出目確定, 到着, ゲーム終了   # 外に見せるのはこれだけ
    非公開: 連鎖深度, 決定表の中身                        # 実装詳細は境界の内側
  }
}

# ============================================
# 横断的性質(検証者エージェントへの攻撃指示)
# ============================================
性質 {
  ルール保存性:
    オフライン版すごろくと同一の出目系列を与えたとき、盤面の遷移は完全に一致する
    # ★最重要。「オンライン化してもゲームは同じ」の機械的検証

  切断の無影響性:
    任意の時点で任意のプレイヤーを切断→60秒以内に復帰させても、
    盤面の履歴は切断がなかった場合と一致する(操作タイミングの遅延を除く)
    # フォールトインジェクション: 全状態で切断を注入

  権威の単一性:
    クライアントが偽の出目・偽の位置を申告しても、サーバーの盤面は影響を受けない
    # 敵対的テスト: 改竄クライアントのシミュレーション

  二重投稿耐性:
    同一コマンドの重複送信(再接続直後の再送など)は高々1回だけ適用される   # 冪等性

  完了保証:
    卓成立した対戦は、有限時間内に必ず ゲーム終了 または 全員離脱 に到達する
    # 停止性(すごろく側) × タイムアウト(対戦側) の合成で保証されるはず→検証
}
```
