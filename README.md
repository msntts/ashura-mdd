# Ashura MDD 🗿

**三つの顔、一つの真実。** AI時代のモデル駆動開発フレームワーク。

## なぜ Ashura か

AIがコードを大量生産する時代、ボトルネックは人間による確認に移った。
Ashura の答えは **ビューの切り替え** — 人間はコードではなく **モデル** をレビューし、
コードの正しさは機械検証に委ねる。

阿修羅の三面のように、一つのシステムを三つのビューで観る:

| 面   | ビュー   | 由来                               |
| ---- | -------- | ---------------------------------- |
| 正面 | **意図** | 人間が承認したモデル(真実の権威)   |
| 側面 | **実装** | コード・実行トレースからの推論     |
| 側面 | **解釈** | AIが仕様文脈から独立導出したモデル |

三面の一致・乖離パターンから問題の所在を機械的に診断する(**三点測量**)。
人間に上がるのは裁定が必要な乖離だけ — レビュー負荷はコード行数ではなく
**ドメインの複雑さ** にのみ比例する。

## 中核原理

1. **モデル権威** — 仕様の真実はモデルのみが持つ。コメントやREADMEは信用しない
2. **人間ゲート** — 承認と乖離の裁定は人間のみ。エージェントは代行できない
3. **AI出力不信** — エージェントの出力は機械検証を通るまで「未検証」
4. **独立導出(共謀防止)** — 検証はモデルの宣言のみから導く。コードを見てテストを作らない
5. **決定性境界** — LSP検査は決定的、エージェント推論は非決定的。担当を混ぜない
6. **優雅な縮退** — モデルで書けない領域(アルゴリズム等)は契約と性質に縮退する。器は壊れない

## 人間が書く(レビューする)もの

構造(クラス図・コンポーネント分割)は書かない。書くのは **振る舞いと制約**:

- **フロー** — イベント / コマンド / ポリシー(イベントストーミング由来)
- **集約** — 状態機械(制御状態+変数)と不変条件
- **決定表** — ルールはデータとして持つ
- **失敗セマンティクス** — フロー×依存の交点に置く(必須/劣化許容/補償/タイムアウト)
- **性質** — 検証者エージェントへの攻撃指示
- **用語集 / コンテキストマップ** — 語彙と信頼境界

判定基準は一つ: **その記述を変えたときビジネス上の意味が変わるか。**
変わらないもの(リトライ回数等)は `steering/` の技術規約へ。

## リポジトリ構成

```
domain/ashura.model.md   # 自己モデル。この環境自身の仕様(ブートストラップ)
steering/                # 技術規約(どう作るか)
examples/                # ケーススタディ4題(DSL表現力の実験記録)
packages/
  ashura-core/           # コアDSL + LSP + サーベイヤー(測量器)
  ashura-dialect-ui/     # UI方言(トークン・合成規則・trait)
  ashura-dialect-game/   # ゲーム方言
docs/decisions/          # ADR(不採用案も記録する)
```

## ケーススタディの結論

同じ器でも、システムの性格ごとに太るセクションが違う。
これ自体がシステムの **診断** になる:

| 題材                   | 太ったセクション          | 型             |
| ---------------------- | ------------------------- | -------------- |
| すごろく               | フロー+決定表             | プロセス駆動系 |
| 電卓                   | 状態機械+性質(契約に縮退) | リアクティブ系 |
| オンライン対戦すごろく | 文脈間+失敗セマンティクス | 統合系         |
| デザインシステム       | 用語集(=トークン)+決定表  | 語彙系         |

全セクションが薄いままなら「モデルを書く価値が薄い」シグナル。

## エージェント構成(予定)

ファシリテーター(対話からモデルを起こす) / ジェネレーター(モデル→コード+トレース表) /
リバースエンジニア(コード→モデル推論) / アドバーサリー(宣言を攻撃する検証者) /
**サーベイヤー(三点測量・乖離検出)** ← 最初に作る。MDDの死因(モデルの腐敗)への対抗策
