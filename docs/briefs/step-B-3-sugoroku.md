# Step B-3: sugoroku.ashura 作成とパース確認

## 前提条件

- B-2 完了(用語集/集約/フロー/決定表/性質/依存をカバーする文法がbuild/test通過)

## 制約(触らないもの)

- `examples/sugoroku-model.md` 自体は「凍結された実験記録」(CLAUDE.mdの禁止事項)。編集しない。翻訳先は新規ファイル `packages/ashura-core/examples/sugoroku.ashura`
- 不変条件式・性質の本文は自由文字列のまま転記してよい(B-2で厳密化しない方針)

## 手順

1. `packages/ashura-core/examples/sugoroku.ashura` を新規作成し、`examples/sugoroku-model.md` の内容を B-2 の文法に翻訳する。**自由文字列(型・不変条件・ガード本文・性質本文・検査文・依存specなど)は必ず `"..."` で引用符付きにする**(裸のFREE_TEXT終端は使わない設計。PLAN.mdのメモ・決定事項を参照)。対応関係:
   - 用語集 すごろく → そのまま `用語集 すごろく { ... }`(各用語の説明は `"..."` で引用符付き)
   - 集約 ゲーム → `状態: 募集中 -> 進行中 -> 終了`、各 `遷移`(`[条件: "..."]` / `[契機: "..."]`)、`禁止`、`変数`(`名前 : "型の説明"`)、`不変条件`(`"..."` の並び)をそのまま構文に載せる
   - フロー 手番進行 → `コマンド`/`イベント`/`ポリシー`/`連鎖上限`/`検査`(`検査: "..."`)を翻訳
   - 決定表 マス効果 → Markdownのパイプ表を `行 "5" -> "移動(-3)" "3マス戻る"` のような行構文に変換する(括弧なし、裸のSTRING。6行: 5, 10, 15, 22, ゴールマス, その他)
   - 性質(停止性・公平性・非決定性の閉包・履歴再現性)→ `性質 { 名前: "..." }`
   - 文脈間の依存(効果音サービス・対戦記録サービス)→ `文脈間 { 依存 名前 ("...") }`(`依存 {` ではなく `文脈間 {` でラップする。B-2でsugoroku側の実際の記法に合わせて確定)

2. **正典サンプルとして内部整合させる**: 原文の集約には `遷移 進行中 -> 終了 [契機: ゴール到達]` があるが、フロー側には `ゴール到達` という名前のイベントが存在しない(決定表の「ゴールマス」行のアクションが「ゲーム終了」になっているのみ)。これは翻訳時に補う暗黙の対応であり、以下のいずれかで整合させる:
   - フロー `手番進行` のポリシー末尾に `ポリシー: 効果解決済み のとき かつ 到着マスがゴールマス のとき -> イベント ゴール到達` に相当する行を追加する
   - もしくは決定表の「ゴールマス」行のアクションを `-> "ゴール到達"` という名前に変更し、フロー側でそのイベント名を明示的に発行する一文を足す
     どちらでも良いが、**フロー内に `ゴール到達` という名前の `EventDecl` が実在する**状態にすること(C-3の正常系判定の前提)。

3. `packages/ashura-core/test/parsing.test.ts`(または新規 `sugoroku.test.ts`)に、`sugoroku.ashura` を読み込んでパースし、`diagnostics.length === 0` であることを確認するテストを追加する。

## 完了確認

- `pnpm -F ashura-core test` で `sugoroku.ashura` のパーステストが green
- `sugoroku.ashura` 内で集約の全ての `契機` がフロー内の実在イベント名を参照している(目視確認。機械検査はC-3で実装)
