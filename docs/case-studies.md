# ケーススタディ実験記録

DSLの表現力はブートストラップと題材で鍛える(Xtextの教訓)。
各題材で「どのセクションが太るか」を観察し、診断仮説を検証した。

| #   | 題材                   | ファイル                          | 発見された構文要求                                            |
| --- | ---------------------- | --------------------------------- | ------------------------------------------------------------- |
| 1   | すごろく               | examples/sugoroku-model.md        | 制御状態/変数の分離、決定表、連鎖上限、境界規則(飽和)         |
| 2   | 電卓                   | examples/dentaku-model.md         | 契約への縮退、網羅性検査(全状態×全入力)                       |
| 3   | オンライン対戦すごろく | examples/online-sugoroku-model.md | 取込(変更禁止/公開イベント)、複数状態機械の積、不採用案の記録 |
| 4   | デザインシステム       | examples/design-system-model.md   | トークン、合成規則、trait要求、人間ゲートが残る層の明示       |

スケール観察(部品数nに対する成長プロファイル):
線形(集約・表) / 一定であるべき(トークン・横断制約・種別) /
O(n²)を種別で殺す(合成規則) / 爆発は機械に押し付ける(検証行列)。
プロファイル逸脱はレビューすべき異常。
