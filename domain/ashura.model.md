# モデル駆動開発環境 自己モデル(仮想DSL)

```
# ============================================
# コンテキストマップ
# ============================================
コンテキストマップ {
  文脈 モデル編集   "人間とファシリテーターがモデルを起こし、育てる"
  文脈 生成         "モデル+規約からコードとトレース表を作る"
  文脈 検証         "モデルの宣言を攻撃し、実挙動を観測する"
  文脈 測量         "三点(意図・実装・解釈)を突き合わせ、差分を裁定に上げる"
  文脈 運用監視     "CIで乖離(drift)を常時検出する"

  関係 モデル編集 -> 生成     (上流/下流: 承認済みモデルのみ引き渡す)
  関係 生成       -> 検証     (成果物とトレース表を引き渡す)
  関係 検証       -> 測量     (観測結果を引き渡す)
  関係 運用監視   -> 測量     (乖離候補を引き渡す)

  # --- 横断制約(この環境の信頼境界) ---
  横断制約 {
    モデル権威:   仕様の真実はモデルのみが持つ。コードのコメント・README の記述は信用しない
    人間ゲート:   承認 は人間のみが発行できる。いかなるエージェントも代行・省略できない
    AI出力不信:   エージェントの出力はすべて「未検証」として生まれ、機械検証を通るまで昇格しない
    独立性:       生成エージェントと検証エージェントは同一の推論文脈を共有しない   # 共謀防止
    決定性境界:   LSP検査は決定的。エージェント推論は非決定的。両者の担当を混ぜない
  }
}

# ============================================
# 文脈: モデル編集
# ============================================
文脈 モデル編集 {

  # --- 集約: モデル成果物 ---
  集約 モデル成果物 {
    状態: 草稿 -> 検査通過 -> レビュー中 -> 承認済み
    遷移 草稿       -> 検査通過   [契機: LSP全検査パス]        # 機械が上げる
    遷移 検査通過   -> レビュー中 [契機: レビュー依頼]
    遷移 レビュー中 -> 承認済み   [契機: 人間の承認]           # 人間だけが上げる
    遷移 レビュー中 -> 草稿       [契機: 差し戻し]
    遷移 承認済み   -> 草稿       [契機: 乖離裁定「モデルを直す」] # 承認は永続ではない
    禁止 草稿 -> 承認済み          # 検査もレビューも飛ばせない

    不変条件 {
      承認済み ならば LSP検査(語彙整合・網羅性・参照整合)をすべて満たす
      承認済み ならば 承認者(人間)と承認時点が記録されている
    }
  }

  フロー ファシリテーション {
    コマンド モデリング開始 -> イベント 対話セッション開始
    ポリシー: 対話中 のとき -> ファシリテーターは 失敗系・禁止遷移・境界規則 を能動的に質問する
      # 「正常系だけ聞いて満足しない」を環境自身の仕様として明記
    ポリシー: セッション終了 のとき -> コマンド 草稿を保存 -> イベント 草稿更新
  }
}

# ============================================
# 文脈: 生成
# ============================================
文脈 生成 {
  フロー コード生成 {
    前提: モデル成果物.状態 == 承認済み        # 未承認モデルからは生成しない
    コマンド 生成する -> イベント 生成完了(コード, トレース表)

    不変条件 {
      トレース表の完全性: モデルの全宣言(遷移・不変条件・性質・失敗セマンティクス)は
                          コード上の対応位置を少なくとも1つ持つ
      # 対応が付けられない宣言があれば 生成失敗 として返す。黙って落とさない
    }

    冪等性: 同一モデル+同一規約からの再生成は、検証結果が等価なコードを生む
      # バイト同一は要求しない(LLM非決定性の受容)。等価性は検証スイートで定義 ←重要な設計判断
  }
}

# ============================================
# 文脈: 検証
# ============================================
文脈 検証 {
  フロー 攻撃 {
    コマンド 検証開始(トレース表)
    ポリシー: 性質宣言ごとに -> 反例探索(プロパティベース / ファジング / フォールト注入)
    ポリシー: 失敗セマンティクス宣言ごとに -> 依存を落として期待挙動を照合
    -> イベント 観測結果確定(合格/反例)
  }

  性質 {
    独立導出: 検証ケースはモデルの宣言のみから導出する。生成されたコードを見て作らない
      # コードに合わせたテストは検証にならない(共謀防止の実装)
  }
}

# ============================================
# 文脈: 測量
# ============================================
文脈 測量 {

  # --- 決定表: 三点測量の裁定(環境の中核ルールはデータとして持つ) ---
  決定表 差分診断 {
    入力: ①意図(承認済みモデル) ②実装(コード由来の推論) ③解釈(AI独立導出) の一致状況
    出力: 診断と宛先

    | ①vs② | ①vs③ | ②vs③ | 診断                     | 宛先                       |
    |-------|-------|-------|--------------------------|----------------------------|
    | 一致  | 一致  | 一致  | 健全                     | 記録のみ                   |
    | 乖離  | 一致  | 乖離  | 実装の逸脱               | 生成へ差し戻し(自動)       |
    | 一致  | 乖離  | 乖離  | 仕様が曖昧(別解釈可能)   | 人間裁定へ ★              |
    | 乖離  | 乖離  | 一致  | モデルが現実と乖離       | 人間裁定へ ★              |
    | 乖離  | 乖離  | 乖離  | 三者バラバラ             | 人間裁定へ(最優先) ★     |

    # ★人間に上がるのは3パターンのみ。それ以外は機械で閉じる ←ボトルネック削減の本体
  }

  # --- 集約: 乖離 ---
  集約 乖離 {
    状態: 検出 -> 裁定待ち -> 解消
    遷移 裁定待ち -> 解消 [契機: 人間裁定(コードを直す | モデルを直す)]
    タイムアウト: 裁定待ち が 7日 を超えたら -> 通知をエスカレーション(放置は仕様腐敗の始まり)
    禁止 検出 -> 解消      # 裁定なしの自動解消はしない(「勝手に直す」の禁止)
  }
}

# ============================================
# 依存と失敗セマンティクス
# ============================================
依存 {
  LSP            (必須,   失敗時: 全工程停止。決定的検査なしでは何も昇格させない)
  LLM推論        (必須,   失敗時: リトライ→劣化(小型モデル)→人間へ手動依頼。非決定的なので出力は常に検証を経る)
  CI基盤         (必須,   失敗時: 乖離検出が止まる。停止中の変更は「未測量」フラグで隔離)
  人間レビュアー (必須,   失敗時=不在時: 承認待ち行列に滞留。エージェントによる代行は しない)
    # 人間を「可用性に限りがある依存」として明示的に扱う ←この環境の設計思想そのもの
}

# ============================================
# 横断的性質(この環境自身への攻撃指示)
# ============================================
性質 {
  ゲート不可迂回性:
    いかなる操作列によっても、人間の承認なしにコードが 生成→本番 に到達しない
    # 敵対的テスト: エージェントに承認省略の抜け道を探索させる

  乖離の可視性保証:
    モデルまたはコードへのあらゆる変更は、有限時間内に必ず 測量 を通過する

  裁定の有限性:
    人間に上がる裁定件数は ドメインの複雑さに比例し、コード行数には比例しない
    # ★当初の目的「確認ボトルネック解消」の検証可能な言明化

  自己適用性:
    この環境自身のモデル(本ファイル)も、モデル成果物 として同じライフサイクルに乗る
    # ブートストラップ: 環境の変更も 草稿→検査→レビュー→承認 を通る
}
```
